# AI SSH 产品设计文档

## 1. 文档目的

本文档用于定义 AI SSH 的产品目标、目标用户、能力范围、架构方向、技术选型以及非功能性要求。

它是后续开发的基础设计文档。今后如果产品定位、架构方向或里程碑范围发生明显变化，必须同步更新本文档以及 `docs/development-plan.md`。

## 2. 产品愿景

打造一个现代化的 SSH 工具：既要有接近原生桌面应用的顺滑体验，又要把 AI 能力做成真正有用、能提升日常运维和开发效率的辅助能力，而不是噱头。

核心体验目标：

- 连接快、终端交互顺滑
- 界面美观、信息密度合理、容易上手
- 服务器与会话管理高效
- 文件浏览、上传、下载足够方便
- AI 能辅助命令、诊断、解释与操作建议
- AI 行为安全、可控、可审计
- 支持 Windows、macOS、Linux 跨平台交付

## 3. 目标用户

### 3.1 主要用户

- 开发者
- DevOps / SRE 工程师
- 后端工程师
- 维护云主机的小团队
- 需要频繁管理远程 GPU / Linux 服务器的 AI 应用开发者

### 3.2 典型使用场景

- 快速连接和切换多台主机
- 管理多个标签页和会话
- 浏览远程目录并进行文件传输
- 查看日志、执行常用命令
- 让 AI 解释报错信息并给出建议
- 通过自然语言生成待审核的 Shell 命令
- 总结当前服务器状态和最近的终端上下文

## 4. 产品原则

- 桌面优先：终端、剪贴板、拖拽、文件传输要尽可能接近本地工具体验。
- AI 是副驾驶，不是自动驾驶：AI 只做建议，不默认代替用户执行。
- 安全默认开启：主机校验、密钥保护、审计日志、权限边界都要前置考虑。
- 先把 SSH 核心能力做扎实，再逐步叠加 AI 和协作能力。
- 架构可复用：虽然首发是桌面版，但核心能力和数据模型要为未来浏览器版本保留复用空间。

## 5. 产品形态决策

### 5.1 方案对比

#### 方案 A：浏览器前端 + 后端服务

优点：

- 浏览器即可访问，使用门槛低
- 集中部署、更新方便
- 更适合未来团队协作或企业托管场景

缺点：

- 终端体验、本地集成体验通常弱于桌面端
- 本地密钥、agent、拖拽上传、文件系统访问更复杂
- 浏览器到后端的数据链路安全复杂度更高
- 离线、本地直连场景体验较差

#### 方案 B：Electron 桌面应用

优点：

- 生态成熟
- 对终端 UI、本地文件系统、托盘、通知、自动更新支持较好
- 与常见前端技术栈兼容性强

缺点：

- 安装包体积和运行内存占用通常更大
- 安全加固需要额外注意
- 用 JavaScript / Node 直接承载 SSH 核心逻辑可行，但不是最理想

#### 方案 C：纯 Go 跨平台应用（原生 UI 或 WebView UI）

优点：

- 非常适合实现 SSH、SFTP、连接管理、并发处理
- 二进制分发方便，资源占用低
- 核心能力更容易沉淀为可复用引擎

缺点：

- 如果走纯原生 UI，产品迭代和界面打磨成本较高
- UI 质感和复杂交互效率通常不如成熟前端生态
- 纯 Go UI 方案的生态选择相对弱一些

#### 方案 D：混合式桌面架构

推荐结构：

- UI：Web 前端
- 桌面壳：Tauri 2
- 核心引擎：Go

优点：

- 保留桌面端体验优势
- 相比 Electron，资源占用更轻
- Go 很适合承载 SSH / SFTP 核心能力
- UI 与连接引擎边界清晰
- 未来仍可复用核心能力到浏览器/服务端架构

缺点：

- 组件更多，工程组织要更清晰
- 需要设计好 IPC 与进程生命周期

### 5.2 推荐结论

推荐采用 **桌面优先的混合式架构**：

- **前端**：React + TypeScript
- **桌面壳**：Tauri 2
- **核心引擎**：Go

这是当前阶段最平衡的方案。

原因：

1. SSH、SFTP、密钥处理、并发会话、文件流传输这些核心能力非常适合用 Go 实现。
2. 如果只做浏览器版，很难把本地集成、拖拽上传下载、密钥与 agent 体验做到足够顺手。
3. Electron 仍然可行，但从资源占用和长期架构清晰度看，Tauri + Go 更适合这个产品。
4. UI 仍然保持 Web 技术栈，界面开发速度和美观度都更容易保障。

## 6. 产品范围

### 6.1 MVP 范围

- 主机管理
  - 保存主机、标签、分组
  - 支持密码、私钥、agent 认证
  - 支持 host key 校验和 known_hosts 管理
- 终端能力
  - 多标签 / 分屏会话
  - 重连与会话状态管理
  - 终端内容搜索
  - 快捷命令 / 常用片段
- 文件管理
  - 远程文件树浏览
  - 上传 / 下载
  - 拖拽传输
  - 基础文件操作：重命名、创建目录、删除、移动
- AI 辅助
  - 解释命令输出和错误
  - 自然语言生成 Shell 命令草稿
  - 给出常见运维任务下一步建议
  - 总结服务器状态和最近上下文
- 易用性
  - 深色 / 浅色主题
  - 键盘快捷键
  - 连接健康状态提示
  - 传输进度与失败重试反馈

### 6.2 MVP 之后的扩展范围

- 端口转发管理
- SSH 隧道模板
- 集群 / 服务器视图
- 多主机批量执行（需审核）
- 远程编辑器联动
- 团队共享与加密同步
- RBAC / 企业策略能力
- 会话录制与更完整的审计链路
- 浏览器伴生版本

## 7. AI 能力设计

### 7.1 AI 典型能力

- 错误解释：把 stderr / stdout 转成易懂说明
- 命令生成：自然语言转命令草稿
- 命令补全建议：根据上下文推荐下一步命令
- 安全提醒：识别高风险命令并提醒
- 日志总结：总结选中的日志内容
- 运维问答：围绕当前会话上下文回答“这台机器上怎么做某件事”
- 目标执行：用户用一句话说明目标后，AI 自动判断是否需要驱动终端，并按审核 / 自动模式推进下一步

### 7.2 AI 交互规则

- 右侧界面只保留一个统一 AI 输入框，不再让用户先选择“助手 / Agent / 解释 / 总结”等模块；系统根据用户输入、选中文本、终端上下文和历史命令自动判断是问答、解释、总结、生成命令，还是驱动终端完成目标；输入框支持 `Ctrl+Enter` / `Cmd+Enter` 快速发送
- 统一 AI 面板必须按时间顺序追加消息：用户输入、流式 thinking、实时输出、最终回答、命令候选、命令执行步骤、执行后的 thinking 和执行结论都保留在同一个对话流中，不允许后续请求覆盖前面的 thinking 或结果；消息区域出现滚动条时自动跟随最新消息
- AI 生成的命令默认不能自动执行
- 用户必须显式审核并确认执行
- 高风险命令必须有额外提醒或确认
- 发给 AI 的敏感信息尽量先脱敏
- 用户必须可以完全关闭 AI 功能
- AI 提供方、模型、Key 和全局系统提示词需要可配置；系统提示词必须有中文默认值，用户可以在设置中覆盖
- 命令预测首条结果作为默认候选；终端当前命令为空时，Tab 循环切换 AI 候选，回车执行当前候选；用户输入其他字符时清空候选
- 终端中框选文本后，选区附近提供“加入 AI”快捷按钮，点击后把选中文本追加到统一 AI 输入框，用户再决定解释、总结或让 AI 继续处理

### 7.3 AI 上下文来源

- 当前终端缓冲区
- 用户选中的文本
- 最近执行过的命令和输出
- 当前工作目录、远程系统信息
- 可选的主机元数据
- 命令预测上下文长度和历史条数可在 AI 预测设置中配置，默认发送最近终端上下文尾部 5000 字符、最近 20 条命令历史、当前命令草稿、主机名、地址和用户名；Go core 会再次将终端上下文限制在最多 50000 字符、历史命令最多 200 条，预测数量默认 3 条、最多 8 条，请求超时 18 秒，模型输出 `max_tokens` 为 1024，并优先请求 OpenAI 兼容 JSON object 响应

### 7.4 AI 提供方抽象

需要设计提供方无关的 AI 服务层：

- 优先支持 OpenAI 兼容接口
- 浏览器前端不直接请求模型服务，先通过 Go core `/api/ai/predict`、`/api/ai/predict/stream`、`/api/ai/assist` 和 `/api/ai/assist/stream` 代理，降低 CORS、日志和未来密钥治理复杂度
- 预留后续本地模型端点支持
- 统一 AI 助手使用 `auto` 意图识别提示词，发送给大模型的系统提示词和用户提示词默认使用中文；命令预测仍使用独立提示词，要求必须返回命令候选
- 统一 AI 对话需要支持新建对话和历史对话列表；历史对话放在 AI 面板内部左侧窄侧栏，默认折叠，展开宽度小于 AI 区域宽度；输入框、审核/自动模式和操作按钮固定在 AI 面板底部，消息流在上方按时间从上到下展示并独立滚动；输入框 Enter 发送、Shift+Enter 换行，发送后立即清空，中文输入法组合态下 Enter 不误触发发送；每个对话只使用当前对话的最近 N 条消息作为上下文，N 可在 AI 设置中配置，默认 30 条；对话和消息持久化保存在 Go core 程序目录下 `data/ai-chat.sqlite3`。消息模型按时间顺序保存用户输入、thinking、最终回答、命令候选、命令执行步骤和执行结论；每条消息，包括用户问题、思考、实时输出、回答、命令、执行步骤、状态和错误，都需要显示 `YYYY-MM-DD HH:mm:ss` 时间；历史对话列表也使用相同时间格式。命令执行完成后更新原步骤消息的状态、输出和退出码，后续 AI 判断继续追加为新的 thinking / 结论 / 下一步命令，不能覆盖前面的历史记录；历史对话可删除，删除时必须从 SQLite 删除对应对话和消息；如果当前新建对话尚无消息，重复点击新建对话应复用当前空对话，避免产生多个空历史记录。
- 统一 AI 对话中的 thinking、实时输出、最终回答、执行结论、步骤说明和错误内容应按 Markdown 预览渲染，支持 GFM 列表、表格、代码块等常见大模型输出格式；当前前端为 React，应使用 React Markdown 预览组件，不使用 Vue 生态的 `md-editor-v3` / `v-md-editor`；界面文案中 thinking 统一显示为“思考”。
- 流式接口使用 SSE，把 provider 返回的 `reasoning_content` 作为 thinking 实时展示，把 `content` 实时展示为原始流；请求结束后 Go core 再解析最终 JSON，清理 thinking / 原始 content，只把结构化回答、命令候选和 Agent 下一步展示为正式卡片
- 使用结构化响应格式承载命令、总结、警告、解释等结果；命令预测必须产出最终 JSON 命令列表，不允许把推理过程放进 `content` 且不给命令；如果模型返回半截 JSON、`commands` 结构残片、空 `content`、`finish_reason=length` 或无法解析的结构化响应，Go core 必须拒绝该结果并记录诊断日志，前端展示前也要再次过滤，不能把结构残片当作可执行命令展示

### 7.5 Agent 任务执行

- Agent 不再作为右侧独立入口暴露，而是统一 AI 输入框中的一种意图；用户输入自然语言目标，例如“安装 nginx 并确认服务启动”“检查 Docker 是否可用并安装缺失组件”后，AI 判断是否需要进入任务执行
- Agent 每次只规划一个下一步命令，并基于终端输出继续判断下一步，直到返回完成、需要用户补充信息或用户停止；统一 AI 返回的普通命令候选在用户点击执行后也进入同一执行闭环：先写入当前 SSH 终端执行，等待远端 prompt / 内部标记拿到输出和退出码，再把执行结果连同任务目标、已执行步骤、步骤输出和退出码继续通过流式 AI 接口发给大模型，让 AI 给出 thinking、结论或下一步命令；如果执行结果已经足以回答用户目标，例如 `which nginx` 返回路径、`nginx -v` 返回版本号或服务状态命令返回明确状态，界面必须展示“执行结论”卡片，用中文说明结论、依据和必要注意事项
- Agent 提供审核模式和自动模式：审核模式下每个命令必须人工点击执行；自动模式下低风险 / 中风险命令可自动执行，高风险命令必须暂停并弹出确认
- Agent 命令、解释、风险级别、风险原因和执行状态需要在右侧 AI 面板中可追踪；用户可跳过某一步或停止任务
- Agent 通过 Go core `/api/ai/assist` 调用 OpenAI 兼容接口，提示词、终端上下文、历史命令和已执行步骤发送前要做基础脱敏；执行命令后优先等待远端 prompt 返回再规划下一步，并通过内部完成标记解析退出码；退出码非 0 仍应作为可解释结果继续交给 AI 判断，例如“未安装”“未找到”“权限不足”，只有命令超时时暂停；本轮已实现 Agent 命令级持久审计：每条执行命令在 SQLite 中生成审计记录，包含会话 ID、对话 ID、命令文本、执行时间、退出码和输出摘要，可通过 Go core API 查询；后续仍需增强流式 UI 观察和复杂 shell 兼容

## 8. 交互与界面设计方向

这个产品应该像一个严肃、顺手的生产力工具，而不是演示性质的 AI 页面。

### 布局建议

- 顶部菜单栏：文件、编辑、会话、传输、工具、设置均采用下拉菜单；文件菜单提供服务器列表导入导出、服务器列表含加密凭据导出、软件配置导入导出等分类型入口；会话菜单提供新建、重连和关闭入口；工具菜单提供运行日志入口，用于排查连接、保存、接口调用和核心服务问题；设置菜单按通用、安全、服务器指标、AI 分组，提供健康检查间隔、刷新频率、指标趋势时间范围、指标圆点数量、终端保留行数、右侧服务器信息默认高度、AI provider、系统提示词、预测数量、预测触发延迟、终端上下文字符数和历史命令条数配置入口；健康检查默认每 10 秒轮询一次，避免频繁打扰日志和网络请求
- 左侧资源栏：SSH 服务器列表、分组、标签；点击加号弹出新增 SSH 连接对话框，点击分组入口可打开分组管理弹窗；每个服务器卡片右上角提供更多菜单，先支持编辑、连接、复制配置和删除；左侧宽度默认保证文件名可读，并支持拖动调整
- 分组管理：分组作为独立配置保存在本地，支持新建空分组、重命名分组、删除未使用分组；重命名分组时会同步迁移该分组下的服务器，已有服务器使用中的分组不能被直接删除，避免主机丢失归属
- 新增连接对话框：填写地址、端口、用户、认证方式，并可从已有分组中选择或输入新分组；可勾选保存密码或 SSH Key；SSH Key 支持粘贴或选择本地私钥文件，保存后连接时自动使用；保存成功后自动关闭并选中新服务器，保存失败在对话框内显示具体错误
- 左侧模式切换：SSH 主机列表与远程文件目录两种模式，文件模式使用 SFTP 展示当前路径的文件和目录，支持路径输入回车进入、上级目录、名称、大小、修改日期、双击进入目录、单击文件选择、Ctrl/Shift 多选文件、双击文件打开预览、上传、选中文件下载和基础传输进度；文件列表表头的名称、大小、修改日期支持点击切换升序 / 降序，文件目录区域获得焦点后支持输入中文或英文字符快速定位匹配的文件 / 文件夹，名称开头匹配优先并滚动高亮到对应行；SFTP 列表需要识别软链接目标，指向目录的软链接按目录展示并支持双击进入；文件和文件夹卡片保持固定高度，数量较少时仍贴顶排列，不随剩余空间拉伸；加载远程文件时在刷新按钮左侧显示旋转图标，不在列表区域单独占用一行；传输任务固定显示在文件面板底部，任务卡片右上角提供关闭按钮，避免滚动到列表末尾才能看到并便于清理记录；桌面客户端支持把系统文件拖入远程文件面板后上传到当前目录，拖入时显示明确的上传目标提示且只创建一条传输任务；客户端下载单个文件和右键下载优先弹出 Tauri 原生保存对话框选择保存地址，批量下载时先选择本地保存目录，再把多个远程文件写入该目录并展示整体进度；远程文件拖出时应通过拖放数据把下载交给系统目标文件夹处理，Windows 桌面端在 WebView2 未接管拖出下载时可尝试识别鼠标所在的资源管理器窗口并下载到该文件夹作为兜底，浏览器调试模式可回退到浏览器下载，后续继续用 Rust 原生文件 promise 补强平台兼容性；空路径、`.` 和相对路径需要在列目录时解析为远端真实绝对路径，避免 home 目录显示成 `.`；跟踪终端路径时优先使用会话输出识别到的当前目录，并用用户输入的 `cd` 命令做本地推断兜底，切换到文件页时可主动读取当前会话路径兜底刷新
- 中间主工作区：SSH 终端会话占据最大面积，顶部提供会话 tabs，用于快速切换不同服务器；标签栏高度固定，打开较多 SSH / 文件预览标签时只在标签栏内部横向滚动，不挤压标签文字、关闭按钮和终端区域；标签栏高度建议约 56px、tab 本体约 40px，用于容纳状态、关闭按钮、文件预览双行标题和细横向滚动条；横向滚动条需要可见且细，不额外压缩标签高度，并支持鼠标滚轮横向滚动和激活标签自动滚入视野；终端容器需要在认证通过并进入工作台后初始化，避免首次启动停留登录页时 xterm 未挂载导致连接后内容为空；文件预览也作为同一标签栏中的 tab 打开，文件预览 tab 和预览头部必须显示所属服务器，避免多服务器文件混淆；打开文件预览时只隐藏终端视图，不销毁 xterm，切回原 SSH 会话或切到其他 SSH 会话都要恢复对应会话的终端缓存并保持可操作；文本文件使用 CodeMirror 打开，默认是只读预览模式，预览、编辑、保存和下载动作保持在头部同一行，支持 `Ctrl+F` 和头部搜索按钮打开搜索面板查找文本；切换编辑模式后显示基于 CodeMirror 命令 API 的工具栏，支持撤销、重做、全选、缩进、反缩进、注释、格式化、还原、复制等常用编辑动作，并可修改 ini、json、shell、Markdown 等常见文本文件后保存回远端，保存成功或失败需要给出明确提示；图片和视频使用媒体预览，未知二进制或不支持直接预览的文件提供下载入口和“以文本方式打开”入口，点击后复用 CodeMirror 文本预览/编辑通道加载展示；文件过大时需要确认后再加载，避免误点导致长时间卡顿；每个 tab 提供无边框关闭按钮和状态圆点，关闭前需要确认，关闭当前 tab 后自动切换剩余会话；每个 SSH 会话保留独立终端输出缓存，默认保存最新 1000 行并可在设置中调整；断开或关闭状态的会话可以在当前 tab 上重连；没有打开会话时不显示伪 tab 和连接状态，只展示空状态和最近服务器快捷连接
- 右侧信息与工具栏：上方显示当前 tab 对应 SSH 服务器信息，并支持折叠 / 展开；CPU、内存、磁盘、网络通过 Go core 读取远端 `/proc` 与 `df` 原始数据解析，展示当前百分比、可配置时间范围折线趋势、多个挂载点列表、实时下载/上传带宽与累计流量；CPU / 内存卡片采用上下布局，顶部左侧显示指标名、右侧显示数值，底部独立展示折线图；内存数值显示已用 / 总量和百分比；CPU / 内存趋势图需要显示 0、50、100% 纵轴与时间横轴，鼠标悬浮时显示具体时间点和使用率，并支持通过图表右上侧无边框放大图标查看大图；小图圆点默认 5 个，放大图圆点默认 20 个；右侧栏默认宽度为 440px，支持拖动调整并持久化到通用设置，当前服务器区域和下方 AI / 历史 / 收藏命令区域之间提供纵向拖拽分隔条，用户可把服务器信息压缩或展开，默认高度可在通用设置中调整；下方 AI、历史命令和收藏命令随右侧剩余高度自适应，AI 面板只保留一个统一输入框和一个按时间排序的消息流，同时展示流式 thinking、实时输出、最终回答、命令候选和任务执行步骤；AI 操作区使用紧凑图标按钮，所有图标按钮必须提供悬浮提示；解释、总结、问答类结果只展示一份最终回答，不显示低 / 中 / 高风险标签；只有需要执行命令的任务步骤才展示风险分级；单条命令卡片保持稳定高度，内容过多时在面板内滚动，不承载连接录入表单
- 命令收藏：AI 预测、历史命令和收藏命令卡片右侧提供执行按钮，点击后直接输入当前终端并回车执行；命令卡片提供复制入口，优先使用紧凑图标按钮，后续可补充右键菜单以减少视觉拥挤；AI 预测和历史命令卡片还提供收藏星标，点击后加入本地收藏命令列表；收藏列表可独立展示、手动添加命令、显示序号、上移 / 下移排序、删除收藏，删除前必须使用应用内确认弹窗，并可点击命令快速填充到当前终端；收藏命令随软件配置导入导出迁移
- AI 预测区域：启用后只针对用户手动输入并由后端确认回显的命令读取当前 SSH 会话的终端上下文和历史命令，通过 OpenAI 兼容流式接口预测下一步命令；触发策略为“命令提交后延迟一段可配置时间再预测”，默认 1000ms，终端持续输出日志不会反复触发，`Ctrl+C` 不取消正在进行的预测；同一会话同一时间只允许一个预测请求在途，预测完成后如果期间又有新手动命令，再排队发起下一次预测；Agent / 统一 AI 自动执行命令期间不触发预测，避免内部完成标记、退出码采集命令和多步骤任务与预测功能互相干扰；预测状态按会话隔离，打开多个 SSH 终端时切换 tab 只展示当前会话自己的预测结果、thinking、流式内容和错误；预测候选卡片放在中间 SSH 终端下方，不再占用右侧 AI 对话区；自动预测开关属于预测区域标题栏，不放在右侧统一 AI 对话区；预测区域展开高度默认约 300px，顶部提供拖动手柄，用户可在约 160px 到 520px 范围内手动调整并持久化高度；收起 / 展开按钮需要明显，收起态略高于标题栏且不出现滚动条，避免流式 thinking 出现和消失时造成终端区域反复跳动；预测必须给出候选，因为是否应用最终由用户人工确认；预测数量、预测触发延迟、终端上下文字符数和历史命令条数可配置，预测数量默认 3 条，上下文默认 5000 字符，历史默认 20 条；流式返回期间先展示 thinking 和原始 content，最终解析成功后自动折叠 thinking，只展示完整命令卡片；只在有真实预测时展示候选列表，不展示固定快捷命令；当前候选仍在终端光标位置以浅灰色提示展示，跟随 xterm 光标、渲染和窗口尺寸变化更新位置；终端当前命令为空时 Tab 循环切换候选，回车执行当前候选；面板需要明确展示启用、等待命令、正在预测、配置缺失、失败和空结果状态，正在预测时使用旋转图标提示

### 关键体验要求

- 连接流程足够快
- 主机 / 会话状态清晰
- 首次启动认证体验：Go core 在没有网页登录密码时不自动生成用户不可见的随机密码，而是返回未初始化状态；桌面客户端、Windows / macOS / Linux 图形客户端，以及仅启动 Go core 的命令行部署，都需要先引导用户设置用户名和登录密码。首次初始化只依赖未初始化状态，不依赖桌面 token，避免调试、重启或复用 core 时因 token 不一致无法保存；登录页和初始化页的密码框提供显示 / 隐藏按钮，便于用户确认输入。网页访问始终需要登录；本机桌面客户端默认允许使用本机安全会话自动进入，可在设置的安全页开启“桌面客户端启动时要求登录”。
- 会话输出流失败、输入接口失败、resize 同步失败或 Go core 重启 / 不可达时，前端不能长期停留在 connecting / connected，必须切换到已断开状态并提示用户查看日志；断开后的会话需要提供明确的重连入口，若后端旧 session 已不存在，应允许用原 hostId 快速创建替代会话并替换当前 tab
- 终端命令历史必须以后端从远端 shell prompt 回显中解析出的最终执行命令为准，前端 xterm 输入流只用于当前命令草稿和 AI 预测交互；这样 Tab 补全、readline 编辑和远端回显后的命令能与 `history` 基本一致，内部路径跟踪、系统探测命令、普通远端输出和终端控制序列不能污染历史；vim、top 等全屏程序进入备用屏幕后不记录历史，历史列表内容过多时独立滚动
- 终端尺寸必须跟随 xterm 实际行列变化同步到后端 PTY，避免 vim 等全屏程序因行列不一致出现错位和残影
- 文件面板跟踪终端路径时优先使用被动 prompt 识别，避免向远端 shell 自动注入额外命令；当 prompt 中的 `~` 被内部映射为相对路径时，SFTP 列表响应仍应返回真实绝对路径；当 prompt 识别尚未到达时，可用用户输入的 `cd` 命令先做本地路径推断
- 终端内容区域必须跟随窗口和中间工作区尺寸变化自动调整 xterm 行列，避免窗口变大后底部留空
- 偏好设置需要显式保存按钮和保存成功反馈
- 主界面应铺满窗口高度，不让页面本身出现全局滚动；左侧资源栏和右侧工具栏内容过多时各自滚动
- 桌面客户端默认窗口高度为 1020px，启动后为终端、文件列表和右侧工具区提供更高可用空间
- 顶部右侧不重复放导入导出按钮，相关能力统一进入文件菜单并按导入/导出对象区分
- 图标按钮和紧凑按钮需要提供悬浮文字提示，避免只靠符号猜含义
- 信息密度高但不拥挤
- 上传下载阻力小
- 文件拖拽在桌面版中应尽量贴近本地体验；系统文件拖入使用 HTML5 拖拽文件对象读取并上传，避免和 Tauri WebView 拖入事件重复触发；远程文件拖出使用 `DownloadURL` / `text/uri-list` 数据让系统按拖放目标下载，后续可通过 Rust 原生文件 promise 继续补强不同平台兼容性
- 支持键盘优先操作
- 空状态、错误状态有良好反馈
- 调试信息可被用户主动查看，保存主机、连接失败、接口异常等问题需要能在运行日志中定位；右侧全局错误提示必须展示来源、接口、状态码、详情和发生时间，并在同一接口后续请求成功时自动清除，避免可恢复错误长期挂住误导用户

### 视觉方向

- 优先打磨深色主题，同时支持浅色主题
- 色彩克制，状态色清晰
- 面板圆角小、布局紧凑
- 图标和排版统一

## 9. 技术架构设计

### 9.1 架构总览

采用三层桌面架构：

1. 表现层
   - React + TypeScript
   - 使用 xterm.js 渲染终端
   - 承载文件管理、AI 面板、设置页、连接视图
2. 桌面集成层
   - Tauri commands / events
   - 负责窗口生命周期、文件选择、托盘、通知、安全本地能力
3. 核心引擎层
   - Go 实现 SSH / SFTP / 会话服务
   - 连接池
   - 传输引擎
   - AI 调度适配层
   - HTTP API 使用 Go 标准库 `net/http`；当前路由规模下不引入额外 Web 框架，后续如果中间件和路由复杂度明显上升，可评估轻量路由库

### 9.2 为什么核心用 Go

- SSH 生态成熟，标准并发模型适合长连接和流式处理
- 更容易实现稳定的会话管理
- 终端流和文件传输性能更好
- 后续更容易沉淀为 CLI、服务端或独立核心引擎

建议在实现阶段重点评估这些包：

- `golang.org/x/crypto/ssh`
- `golang.org/x/crypto/ssh/agent`
- `golang.org/x/crypto/ssh/knownhosts`
- `github.com/pkg/sftp`

### 9.3 进程模型

推荐模式：

- Tauri 启动 Go sidecar 作为受控子进程
- 前端通过 Tauri 层调用本地能力
- Tauri 与 Go 之间通过结构化 IPC 通信
- 终端流和传输进度通过事件或流式消息向前端推送

这样做的好处：

- SSH 逻辑不暴露给前端运行时
- 进程隔离更利于崩溃恢复和稳定性
- 安全边界更清楚

### 9.4 核心数据模型

关键实体建议包括：

- Host
- CredentialRef
- Session
- TransferTask
- AISuggestion
- CommandTemplate
- Setting

## 10. 安全设计

安全不是后补功能，而是 MVP 要求的一部分。

### 最低要求

- 敏感凭据优先存入操作系统安全存储
- 严格 host key 校验，提供可管理的首次信任流程
- 区分“持久保存凭据”和“仅本次会话使用”
- Agent 命令级审计：Agent 执行的每条命令持久记录到 SQLite 审计表，包含会话 ID、对话 ID、命令文本、执行时间、退出码和输出摘要，支持通过 Go core API 查询审计列表
- 记录 AI 生成命令与用户执行行为的审计信息
- AI 默认不静默执行命令
- 向 AI 发送上下文前支持脱敏

### 安全边界

- 前端尽量不直接管理原始 SSH 密钥
- 连接建立与凭据使用由核心引擎负责
- Tauri 能力范围尽量最小化、显式化

## 11. 本地数据存储

推荐本地持久化方式：

- MVP 阶段先使用 JSON 保存服务器基础配置，默认路径为 Go core 可执行文件所在目录下的 `data/hosts.json`
- 调试模式、桌面打包模式和命令行 / Web 打包模式都遵循“Go core 程序所在目录下的 `data`”规则；不再提供数据根目录环境变量覆盖，必要时可通过 `AI_SSH_HOSTS_PATH` 精确覆盖 `hosts.json` 文件路径
- 密码与 SSH Key 默认通过操作系统安全存储保存，并在连接前由 Go core 读取使用；较长 SSH Key 需要分片写入以兼容系统凭据长度限制
- 导出分为普通导出和含加密凭据导出：普通导出不携带密码/SSH Key；含加密凭据导出使用一次性 `exportKey` 加密凭据，目标电脑导入后解密并写入当地系统安全存储
- SQLite：存业务元数据
- OS Keychain / Credential Manager：存敏感凭据
- 本地结构化日志：存调试和审计信息，前端提供运行日志面板，可查看前端请求、Go core 请求、保存失败原因，并可设置和按 `debug`、`info`、`warn`、`error` 日志级别筛选展示，支持按关键字搜索日志等级、来源、消息和字段；Go core 默认不记录成功的 `/health` / `/api/health` 请求，运行日志面板提供“记录健康检查”开关，需要排查 core 轮询时可临时打开，异常健康检查仍应记录；AI provider 预测失败时需要以错误级别记录状态码、响应体片段、模型输出片段、解析失败原因和耗时，避免只暴露 `no commands` 这类笼统提示，日志中不得记录 API Key 或完整终端上下文

主要数据类别：

- 主机与分组
- UI 偏好
- 命令历史 / 片段
- 传输历史
- AI 设置与审计记录

## 14. 结论摘要

最终推荐方案：

- **产品形态：桌面优先**
- **UI 技术：Tauri 2 + React + TypeScript**
- **核心引擎：Go**
- **架构原则：为未来浏览器 / 服务端复用预留核心能力**

这个组合在以下维度上最平衡：

- 用户体验
- 跨平台交付
- SSH 可靠性
- 性能
- 安全性
- 长期扩展性
