# docs 模块

## 职责

`docs/` 目录集中管理 AI SSH 项目的所有文档资产，包括产品设计、开发计划、使用指南和模块索引。本模块不包含可执行代码，其"交付物"是准确、可执行、与代码同步的文档。

## 目录说明

| 文件 | 用途 | 目标读者 | 更新触发条件 |
|------|------|----------|-------------|
| `product-design.md` | 产品愿景、架构决策、技术选型、安全设计、产品范围 | AI、开发者、产品决策者 | 架构方向、产品范围或技术选型变更 |
| `development-plan.md` | 里程碑拆分、交付物、工程规则、进度状态、风险 | AI、开发者 | 里程碑调整、范围变化、进度更新 |
| `run-and-preview.md` | 本地启动、调试方式、常见问题排查 | 开发者、使用者 | 新增启动方式、端口/命令变化、新增排查项 |
| `build-and-package.md` | 打包流程、产物说明、脚本参数 | 开发者、打包者 | 打包流程变化、新打包目标、脚本参数变更 |
| `user-guide.md` | 用户使用说明（功能操作指南） | 最终用户 | 新增功能、UI 流程变化 |
| `MODULE_INDEX.md` | 模块清单、职责、维护文档路径、验证方式 | AI、开发者 | 新增/删除/重命名模块 |
| `MODULE.md` | 本文件，docs 模块自身说明 | AI、开发者 | 文档结构或更新规则变化 |
| `images/` | README 和文档引用的截图 | — | 界面重大变化时更新截图 |
| `image-detail/` | 功能细节截图 | — | 界面重大变化时更新截图 |

英文版（`*-en.md`）为对应中文文档的翻译版本，应与中文版保持同步。

## 更新规则

1. **代码优先**：文档描述必须基于代码事实。如果文档与代码冲突，以代码为准，并修正文档。
2. **同步更新**：修改代码接口、配置、行为或流程时，必须同步检查并更新相关文档。
3. **范围对应**：
   - 架构/产品方向变化 → 更新 `product-design.md`
   - 里程碑/进度变化 → 更新 `development-plan.md`
   - 启动/调试方式变化 → 更新 `run-and-preview.md`
   - 打包流程变化 → 更新 `build-and-package.md`
   - 模块变化 → 更新 `MODULE_INDEX.md`
4. **新增模块**：任何新增模块必须在 `MODULE_INDEX.md` 中登记，并提供对应路径和职责摘要。
5. **语言一致性**：中文文档为主；英文版应跟随中文版更新。

## 验证方式

文档自身无自动化验证。通过以下方式保证质量：
- 代码变更时由 AI/开发者人工核对相关文档是否需要更新。
- 新增模块时检查 `MODULE_INDEX.md` 是否登记。
- 文档引用的命令（如 `npm run dev:core`）需在 `package.json` 中存在。

## 常见改动点

- **新增功能模块**：在 `MODULE_INDEX.md` 登记，同时在 `README.md` 文档区添加链接。
- **修改默认端口或路径**：需同步更新 `run-and-preview.md`、`build-and-package.md`、`AGENTS.md` 中的相关命令。
- **里程碑推进**：更新 `development-plan.md` 中的完成状态和进度说明。
- **技术选型变更**：更新 `product-design.md` 并同步影响分析到 `development-plan.md`。
